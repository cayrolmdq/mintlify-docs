Esta guía describe todo lo que puede hacer una persona usando Gastuki. El canal
principal es **WhatsApp** (texto, audio o imagen); la **web app** complementa con
vistas detalladas y formularios. La API REST que respalda ambas superficies se
monta en la raíz (`/expenses`, `/income`, etc.) y requiere token Bearer de
Supabase salvo que se indique lo contrario.

<Note>
  Todos los endpoints de esta sección usan **camelCase** en request/response. Las
  rutas `/merchant/*` (documentadas en [Comercios](/comercios)) usan snake_case.
</Note>

## 1. Registro de gastos

**Qué hace.** El usuario registra un gasto describiéndolo en lenguaje natural.
La IA extrae el **monto**, la **categoría**, el **comercio/descripción** y la **fecha**.

**Cómo se usa (WhatsApp):**
- Texto: `gasté $500 en pan`, `pagué 300 café`, `$50 alfajor`
- Audio: el mensaje de voz se transcribe y se procesa igual que el texto.
- Imagen: una foto del ticket se procesa por OCR para extraer el monto.

**Comportamiento clave:**
- **Categorización automática** según el contexto (ej.: "pan" → Alimentos).
- **Detección de comercio**: si el gasto se asocia a un comercio activo, puede
  disparar sellos de fidelidad y/o invitación a la ruleta.
- **Confirmación con saldo**: la respuesta muestra el progreso del mes y el saldo
  si el usuario tiene ingresos u objetivos cargados.
- **Confirmación opcional por formulario** (feature flag): en vez de crear el
  gasto directo, se envía un formulario de WhatsApp para revisar/editar antes de
  confirmar. Si el formulario falla, se crea el gasto directamente (degradación
  elegante).

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `POST` | `/expenses` | Crear gasto |
| `GET` | `/expenses` | Listar gastos del mes actual |
| `GET` | `/expenses/:id` | Detalle de un gasto |
| `PATCH` | `/expenses/:id` | Editar gasto |
| `DELETE` | `/expenses/:id` | Eliminar gasto |
| `GET` | `/expenses/month-total` | Total gastado en el mes |

<Tip>
  Editar/borrar también es posible respondiendo el mensaje de confirmación en
  WhatsApp (p. ej. "borrar").
</Tip>

## 2. Registro de ingresos

**Qué hace.** El usuario registra dinero que entra (sueldo, freelance, regalos,
transferencias).

**Cómo se usa (WhatsApp):**
- `ingreso $1000 salario`, `recibí 500 freelance`, `me pagaron 5000`
- Con fecha opcional: `ingreso $2000 salario 15/10`

**Comportamiento clave:**
- Soporta **categorías libres** (no predefinidas).
- Las transferencias entrantes pueden registrarse automáticamente como ingreso
  (ver sección siguiente).
- Calcula **saldo neto** (ingresos − gastos) para mostrar en confirmaciones.

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `POST` | `/income` | Crear ingreso |
| `GET` | `/income` | Listar ingresos por rango |
| `GET` | `/income/all` | Todos los ingresos |
| `GET` | `/income/:id` | Detalle |
| `PATCH` | `/income/:id` | Editar |
| `DELETE` | `/income/:id` | Eliminar |

## 3. Detección de transferencias

**Qué hace.** Cuando el usuario envía la captura de un comprobante de
transferencia, el sistema extrae los datos y decide si es un **ingreso** (la
transferencia entra a una cuenta verificada del usuario) o un **gasto**.

**Cómo se usa:** se envía por WhatsApp la imagen/PDF del comprobante.

**Comportamiento clave:**
- Funciona con transferencias argentinas (formato **CBU/CVU**).
- Requiere tener una cuenta bancaria **verificada** (ver sección 13) para que el
  match destinatario marque la operación como ingreso.
- **Idempotente**: previene registrar dos veces la misma transferencia.

**Endpoints relacionados:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `GET` | `/bank-accounts/transfers` | Listar transferencias detectadas |
| `GET` | `/bank-accounts/transfers/:id` | Detalle de una transferencia |

## 4. Lista de compras

**Qué hace.** El usuario mantiene una lista de cosas por comprar (no son gastos
todavía, son pendientes).

**Cómo se usa (WhatsApp):**
- Agregar: `agregar leche`, `necesito tomates`, `lista: pan, leche, huevos`
- Con cantidad: `2 kg arroz`, `1 litro leche`
- Borrar: `borrar leche`, `quitar pan`, `eliminar: leche, huevos`
- Combinado: `agregar pan, leche / borrar tomates` (agrega y borra en un mensaje)

**Comportamiento clave:**
- Soporta **cantidades y unidades** opcionales.
- **Deduplica**: no agrega el mismo ítem dos veces.
- La confirmación incluye link para ver la lista en la web app.

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `GET` | `/shopping-list` | Ver lista actual |
| `POST` | `/shopping-list` | Agregar ítem(s) |
| `DELETE` | `/shopping-list` | Vaciar la lista |
| `PATCH` | `/shopping-list/:id` | Editar ítem (nombre/cantidad) |
| `DELETE` | `/shopping-list/:id` | Borrar un ítem |

## 5. Objetivos / presupuestos

**Qué hace.** El usuario define límites de gasto (mensual total o por categoría)
y ve su progreso.

**Cómo se usa (WhatsApp):**
- Crear: `objetivo $100000 este mes`, `presupuesto comida $30000`
- Actualizar: `objetivo comida $25000`
- Eliminar: `eliminar objetivo comida`, `borrar objetivo total`
- Ver: `ver objetivos`, `mis objetivos`, `presupuesto`

**Comportamiento clave:**
- Dos tipos: **total** (tope mensual) y **categoría** (límite por categoría).
- Muestra **gastado vs. objetivo** con porcentaje, actualizado en tiempo real al
  registrar gastos.
- Normaliza variantes en español de las categorías (comida/alimentos, etc.).

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `GET` | `/budget-goals` | Listar objetivos con progreso |
| `POST` | `/budget-goals` | Crear objetivo |
| `PATCH` | `/budget-goals/:id` | Actualizar monto |
| `DELETE` | `/budget-goals/:id` | Eliminar |

## 6. Cupones

**Qué hace.** El usuario puede canjear cupones (descuentos/beneficios) que crean
los comercios. Los cupones también se generan automáticamente al completar una
tarjeta de sellos o por campañas de recupero.

**Cómo se usa (WhatsApp):** `canjear COUPON123`, `cupón ABC456`.

**Comportamiento clave:**
- El usuario debe estar registrado.
- Validación: el cupón debe existir, estar vigente, no estar agotado y el comercio
  activo.
- La respuesta confirma el premio/beneficio y el código.

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `GET` | `/coupons/available` | Cupones disponibles para canjear |
| `GET` | `/coupons/redeemed` | Cupones ya canjeados |
| `GET` | `/coupons/:id` | Detalle de un cupón |

## 7. Happy Moments / Ruleta

**Qué hace.** Tras registrar un gasto en un comercio participante, el usuario
puede **girar una ruleta** para ganar un premio (cupón) o no ganar nada.

**Cómo se usa:** la confirmación del gasto incluye un link a la ruleta
(`.../ruleta?expenseId=...`); el usuario toca para girar.

**Comportamiento clave:**
- Elegibilidad según la configuración del comercio: campaña activa, monto mínimo,
  límite de giros por día, cantidad mínima de compras previas, etc.
- Resultado **ponderado** (probabilístico). Si gana, recibe un cupón al instante.
- **Un giro por gasto** (idempotente).

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `POST` | `/happy-moment/spin` | Girar (body con `expenseId`) |
| `GET` | `/happy-moment/spin/:expenseId` | Estado/resultado del giro |
| `GET` | `/happy-moment/available` | Happy Moments disponibles para el usuario |

## 8. Sellos y tarjetas de fidelidad

**Qué hace.** El usuario acumula **sellos** en comercios participantes. Al llegar
a la cantidad requerida, obtiene una recompensa (cupón).

**Cómo se usa (flujo):**
1. El comercio expone un **QR**.
2. El usuario lo escanea → se abre WhatsApp con el nombre del comercio precargado.
3. Registra el gasto → el sistema vincula la compra al comercio y otorga el sello.
4. Algunos sellos requieren **aprobación del comercio** antes de impactar.
5. Al completar la tarjeta, se genera un cupón automáticamente.

**Comportamiento clave:**
- El usuario tiene un **saldo de sellos por programa**.
- La web app muestra el progreso de cada tarjeta.

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `GET` | `/stamps/myPrograms` | Programas de fidelidad y progreso del usuario |

## 9. Referidos

**Qué hace.** Cada usuario tiene un **código de referido**. Cuando alguien se
registra usando ese código, ambos pueden obtener beneficios (chances en sorteos,
bonus, etc.).

**Cómo se usa:**
1. El usuario obtiene su código.
2. Lo comparte; el nuevo usuario lo ingresa al registrarse.
3. Se valida y se registran ambos.

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `GET` | `/referrals/my-code` | Obtener mi código |
| `POST` | `/referrals/validate` | Validar un código antes de aplicarlo |
| `POST` | `/referrals/apply` | Aplicar código al usuario actual |

## 10. Campañas y sorteos

**Qué hace.** El usuario se inscribe en campañas temporales (ej.: promo navideña)
para sumar **chances** en un sorteo.

**Cómo se usa:**
1. Se anuncia una campaña con nombre único (ej.: `navidad`).
2. El usuario se inscribe (suele pedir su usuario de Instagram para anunciar al
   ganador).
3. Suma chances por: inscripción, actividad semanal (días distintos con gastos) y
   referidos válidos.
4. Al cierre, se sortea entre todas las chances.

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `POST` | `/campaigns/:campaignName/register` | Inscribirse |
| `GET` | `/campaigns/:campaignName/me` | Mi estado y desglose de chances |
| `GET` | `/campaigns/:campaignName/referrals` | Mis referidos en la campaña |
| `GET` | `/campaigns/:campaignName/config` | Reglas y fechas de la campaña |

## 11. Resumen semanal

**Qué hace.** El sistema envía automáticamente un resumen del gasto semanal.

**Contenido típico:**
- Total gastado en la semana.
- Top categorías con porcentaje.
- Comparación semana contra semana.
- Progreso de objetivos y cupones canjeados.

**Comportamiento clave:**
- Se envía solo si hubo al menos un gasto en la semana.
- Una vez por usuario por semana (sin duplicados).

## 12. Validación de teléfono

**Qué hace.** Verifica la propiedad del número mediante un **código OTP** enviado
por WhatsApp. Es requisito para crear/enlazar la cuenta y habilitar features.

**Cómo se usa:**
1. El usuario ingresa su teléfono en la web.
2. El sistema chequea disponibilidad y envía el OTP.
3. El usuario responde con el código → se verifica y se crea el perfil si es nuevo.

**Comportamiento clave:**
- **Rate limiting** en el chequeo de disponibilidad (protección anti-abuso).
- El OTP expira; cada nuevo pedido invalida el anterior.

**Endpoints:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `POST` | `/phone-validation/request` | Enviar OTP |
| `POST` | `/phone-validation/request/v2` | Enviar OTP (plantilla v2) |
| `POST` | `/phone-validation/verify` | Verificar OTP |
| `GET` | `/phone-validation/status/:phone` | Estado de validación |
| `POST` | `/phone-validation/availability` | ¿El teléfono está disponible? |

## 13. Verificación de cuenta bancaria

**Qué hace.** El usuario demuestra que es dueño de una cuenta (CBU/CVU) para
mejorar la detección de transferencias como ingresos.

**Flujo:**
1. Registra el CBU/CVU (y opcionalmente el titular).
2. Hace una transferencia de prueba ($100) a la cuenta de Gastuki.
3. Sube el comprobante.
4. Un administrador revisa y aprueba/rechaza manualmente.
5. Al aprobarse, la cuenta queda vinculada al perfil.

**Estados:** `pending` → `proof_received` → `approved` / `rejected`.

**Endpoints (requieren auth):**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `POST` | `/bank-accounts/verifications` | Registrar cuenta a verificar |
| `POST` | `/bank-accounts/verifications/:id/proof` | Subir comprobante (multipart) |
| `GET` | `/bank-accounts/verifications/:id` | Estado de la verificación |
| `GET` | `/bank-accounts/verifications` | Listar mis verificaciones |
| `DELETE` | `/bank-accounts/verifications/:id` | Eliminar una verificación |

**Incluye:** teléfono validado, nombre, cuentas bancarias vinculadas, datos para
campañas.

**Endpoints:**

## 16. FAQ y ayuda

**Qué hace.** El usuario hace una pregunta y el sistema responde con la entrada de
FAQ más relevante usando IA. Los saludos también se tratan como pedido de ayuda.

**Cómo se usa (WhatsApp):** `¿cómo registro un gasto?`, `hola`, `¿puedo dividir
gastos?`.

**Comportamiento clave:**
- 100% basado en prompts: la base de FAQ no está hardcodeada.
- Si no hay buena coincidencia, devuelve una pista sobre las features disponibles.

## 17. QR de comercios

**Qué hace.** Un QR del comercio abre WhatsApp con un mensaje precargado para que
el usuario registre el gasto y quede atribuido a ese comercio (sellos/analítica).

**Cómo se usa (usuario):** escanea el QR en el local → se abre WhatsApp con el
nombre del comercio precargado → completa el monto y envía.

**Endpoint público:**
| Método | Ruta | Descripción |
|--------|------|-------------|
| `GET` | `/qr/:merchantCode` | Redirige a WhatsApp con el mensaje del comercio |

<Note>
  El mensaje precargado prioriza una plantilla personalizada del comercio; si no
  existe, usa una autogenerada del tipo *"Hoy fui a '\{comercio\}' y gasté $"*.
</Note>

## 18. Recordatorios

**Qué hace.** El sistema envía recordatorios por WhatsApp a usuarios que dejaron
de registrar gastos, para reactivarlos.

**Comportamiento clave:**
- Se envían solo en **horario diurno** (Argentina).
- **Uno por usuario por período** (sin spam).
- Rota entre varias plantillas para no repetir el mismo mensaje.
